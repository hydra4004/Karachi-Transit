# 07 — Iteration Log

Two kinds of iteration are recorded here.

- **Section A — build-time iterations.** These are real: each problem below was actually found, fixed and re-verified with the automated test suites. They are marked as build-time because they were found by the team and by the automated checks, not by a study participant.
- **Section B — study iterations.** These must come from your own test sessions. One row per problem found in a session, with before/after screenshots attached. Replace the `[FILL]` cells.

## Section A — Build-time iterations (already done, verifiable)

| # | Round | Problem observed | Evidence | Change made | Principle applied | Verified by |
| --- | --- | --- | --- | --- | --- | --- |
| A1 | Build | The SOS hold never started its countdown, so a tester could not cancel it — the confirm step was unreachable | Browser test: `FAIL holding for 2 s starts the cancel countdown (IR3)` | The hold was rewritten from `requestAnimationFrame` to a 30 ms timer driven by `Date.now()`, and the release handler was moved to `window` so letting go anywhere ends the hold | Error prevention, user control | `ui.test.html` now: "holding for 2 s starts the cancel countdown", "cancel is visible during the countdown" |
| A2 | Build | The journey planner could not plan a trip whose two stops were served by different, unconnected parts of the network (e.g. a chinchi point in the north to a bus stop in the south) | Engine test: `FAIL fallback planner generates a route for an unprepared pair` | The planner was rebuilt as a breadth-first search over two edge types — route legs and short walk legs (stops within 46 px are treated as the same place) — with ranking that prefers bus legs over chinchi legs | Reduce cognitive load, match with the real world | `engine.test.js` now: "fallback planner generates a route for an unprepared pair" (218/218 pass) |
| A3 | Build | The planner produced steps that always began with a "change to" card, even for a single-vehicle journey, and could not describe a walk | Code review of `planFromLegs()` | Each leg now carries a `kind` (`route` or `walk`); a transfer card is only inserted between two route legs, and a walk card explains that the two stops are the same place | Explainability | `ui.test.html`: "planner returns a multi-vehicle journey (4 steps)" |
| A4 | Build | With the connection down the map went blank and the ETA cards still claimed to be **Live** — the app was lying about how fresh the data was | Requirement review against IR5 | The simulation clock is now frozen at the moment the connection is lost, vehicles keep their last known coordinates, the banner shows the age of the last update, and every Live badge becomes "Last known" | Visibility of system status, help users recover from errors | `ui.test.html`: "the banner states the age of the last update", "no ETA claims to be live while offline" |
| A5 | Build | There was no way to demonstrate a dropped connection at all — `state.offline` was never set | Code review | Added a "Simulate connection loss" switch in More, and the app also listens for the browser's own `online`/`offline` events | Help users recover from errors | `ui.test.html`: "dropping the connection shows an offline banner (IR5)" |
| A6 | Build | The map could not be tapped: the vehicle layer sat on top of the stop points and swallowed the clicks | Browser test: "tapping a chinchi point opens the stop sheet" failed | The vehicle layer was given `pointer-events:none`, and the stop hit areas were enlarged | Consistency and standards | `ui.test.html`: "tapping a chinchi point opens the stop sheet" |
| A7 | Build | Searching for something that did not exist produced a blank area under the search box | Code review of `renderSearchResults()` | An explicit "no results" message was added, in both languages | Help users recover from errors | `engine.test.js` + `ui.test.html` |
| A8 | Build | Every one-second refresh re-rendered the whole screen, which made long lists jump while the tester was reading | Code review of `refreshDynamic()` | Only the dynamic parts are re-rendered, and the scroll position of the active screen is restored after each refresh | Reduce cognitive load | Manual check in the browser test (no scroll jump) |
| A9 | Build | The ETA calculation threw a `TypeError` on some vehicles, because the delay field was read from the wrong object | Engine test: vehicle state check | The delay is read from the vehicle state, not from the raw vehicle record | Visibility of system status | `engine.test.js` — 218/218 pass |
| A10 | Build | The union portal's alert preview did not show the exact sentence the commuter would read, so the operator could not check their wording before publishing | Code review of `buildMessage()` | The preview is generated by the same function that writes the alert, so preview and published text are identical by construction | Feedback | `sync.test.html`: "portal shows the message the commuter will read" |
